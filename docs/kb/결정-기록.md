## 처음 만들 때의 선택

### 언어: Python 표준 라이브러리만
- **결정**: Python 3, 외부 패키지 없음. 웹 프레임워크 없이 표준 `http.server`만 사용.
- **이유** [코드]: 설치 없이 `python3 server.py` 한 줄로 바로 띄우기 위해서입니다(`_reference_clean/server.py` 머리말에 "설치 불필요"라고 적혀 있음). 이 Mac의 기본 Python 3.9로 바로 돌아갑니다.
- **영향**: Python 3.10 이상 문법(`match` 등)은 쓰지 않습니다. 테스트도 pytest가 아닌 기본 `unittest`로 만들었습니다.

### DB: SQLite 파일 하나 (`survey.db`)
- **결정**: 서버 파일 옆의 SQLite 파일 하나에 저장.
- **이유** [코드]: 별도 DB 서버가 필요 없고, 파일만 복사하면 옮겨집니다. 노트북 한 대에서 팀 단위로 쓰는 규모라 충분합니다.
- **레거시 흔적** [코드]: 원본 주석에 "MySQL 로 바꿀 예정이라 임시로 sqlite 씀 - 2009"가 있지만, 바꾸지 않았습니다.

### 질문 형식: 문항을 JSON 한 칸에 저장
- **결정**: 설문의 문항 목록을 `surveys.questions` 칸에 JSON 배열로 통째로 저장. 답은 `answers` 테이블에 `(응답, 문항 id, 값)` 한 줄씩 저장.
- **이유** [추정]: 문항 타입이 7가지이고 타입마다 붙는 정보(선택지, 점수 범위, 기타 허용)가 달라서, 표로 나누는 것보다 JSON이 단순합니다. 대신 답은 집계해야 해서 행으로 나눴습니다.
- **결과로 생긴 규칙** [코드]: 응답이 하나라도 있는 설문은 **문항을 못 바꿉니다**(제목·안내만 가능). 문항 id가 바뀌면 기존 답과 연결이 끊기기 때문입니다. 문항을 바꾸려면 "복사해서 새 설문"을 씁니다.
- **문항 타입 7가지** [코드]: 단답, 장문, 점수(1~5 또는 1~10), 하나 고르기, 여러 개 고르기, 예/아니오, 날짜. 고르기 문항에는 "기타(직접 입력)"를 켤 수 있습니다.

### 익명성
- **결정** [코드]: 응답자의 이름, IP, 쿠키 값을 저장하지 않습니다. 서버 로그에도 IP를 남기지 않습니다. 주관식 답은 무작위 순서로 보여줍니다(응답 순서로 누가 썼는지 짐작하지 못하게).
- **대가**: 중복 응답은 브라우저 쿠키로만 막습니다. 시크릿 창으로는 여러 번 응답할 수 있습니다.

### 관리 기능: 로그인 대신 "이 노트북에서만"
- **결정** [코드]: 관리 화면과 관리 API는 서버를 띄운 노트북에서 `localhost`로 접속할 때만 열립니다. 비밀번호가 없습니다.
- **이유** [추정]: 수업이나 팀 회의에서 진행자 노트북 한 대로 운영하는 상황을 가정했습니다. 와이파이(`HOST=0.0.0.0`)로 공유해도 다른 기기에서는 응답과 결과만 볼 수 있습니다.
