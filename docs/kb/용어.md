# 용어

같은 것을 여러 이름으로 부르면 헷갈리니, 문서와 대화에서는 아래 이름으로 통일합니다. 괄호 안은 코드와 DB에서 쓰는 이름입니다.

| 용어 | 뜻 | 코드·DB |
|---|---|---|
| **설문** | 제목, 안내 문구, 문항 목록을 묶은 하나의 조사 | `surveys` 테이블 한 줄 |
| **설문 코드** | 설문 주소에 들어가는 소문자·숫자 7자. 응답자에게 공유하는 값 | `slug` (API에서는 `code`) |
| **문항** | 설문 안의 질문 하나. 종류(타입)와 필수 여부가 있음 | `questions` JSON 배열의 항목 (API에서는 `q`) |
| **문항 타입** | 단답 `text`, 장문 `textarea`, 점수 `rating`, 하나 고르기 `single`, 여러 개 고르기 `multi`, 예/아니오 `yesno`, 날짜 `date` | `type` |
| **선택지** | 하나 고르기·여러 개 고르기 문항의 보기 | `options` |
| **기타** | 선택지에 없는 답을 직접 적는 칸. 켜 둔 문항에만 나옴 | `allowOther`, 저장값 `__other__`, 적은 내용 `other_text` |
| **응답자** | 설문에 답하는 사람. **누군지 저장하지 않음**(이름, IP, 쿠키 값 모두 저장 안 함) | — |
| **응답** | 응답자가 제출하기를 한 번 누른 것. 한 사람이 한 번 제출하면 응답 1개 | `responses` 테이블 한 줄 (API에서는 `cnt`가 응답 수) |
| **답** | 응답 안에서 문항 하나에 대한 값. 여러 개 고르기는 고른 개수만큼 답이 생김 | `answers` 테이블 한 줄 |
| **요약** | 문항별로 답을 모아 센 것. 점수 분포, 평균, 선택지별 개수, 주관식 목록 | `/api/getResult`의 `results` (화면 이름은 "결과") |
| **응답 받기 / 마감** | 응답을 받는 상태 / 더 받지 않는 상태. 새 설문과 복사본은 마감 상태로 시작 | `is_open` 1 / 0 (API에서는 `open`) |
| **응답 초기화** | 설문은 남기고 응답만 모두 지우기 | `cmd: "reset"` |
| **관리자** | 서버를 띄운 노트북에서 localhost로 접속한 사람. 로그인은 없음 | `is_local()` |
| **이미 응답함** | 이 브라우저에 그 설문의 쿠키가 있는 상태. 중복 응답은 이것으로만 막음 | 쿠키 `sv_<설문 코드>`, API `already` |

## 헷갈리기 쉬운 것

- **응답 vs 답**: "응답 3개"는 3명이 제출했다는 뜻이고, "답"은 그 안의 문항별 값입니다. 결과 화면의 "N명 응답"은 응답 수입니다.
- **결과 vs 요약**: 화면과 API 이름은 "결과"(`result.html`, `getResult`)지만, 내용은 원본 답이 아니라 **요약**입니다. 원본 답 전체가 필요하면 CSV를 받습니다.
- **엑셀 vs CSV**: API 이름은 "엑셀"(`/api/excel`)이지만 실제 파일은 CSV입니다. 화면 버튼은 2026-11-06부터 "CSV 다운로드 (엑셀용)".
- **설문 코드 vs id**: 응답자에게는 **코드**만 보입니다. 숫자 **id**는 관리 화면 안에서만 씁니다.
